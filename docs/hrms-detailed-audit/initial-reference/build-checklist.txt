4. APPLY LEAVE — OBSERVED
Paid Leave and Permission Leave; start date, end date, required reason;
optional PDF/DOC/JPG/PNG attachment (UI states maximum 5MB); submit and reset.
Shown policy: Paid Leave earns one day/month and carries forward; Permission
Leave is unlimited and unpaid with no quota deduction. Weekends and company
holidays do not count as leave; IT text explicitly mentions Saturday + Sunday.
Guide additionally says paid leave never expires and cannot be used on Mondays
or Fridays; only Permission Leave can be used on those days. Confirm these rules.
Unknown: accrual start/proration, backdating, notice periods, overlap handling,
partial days, date validation, concurrent balance updates, actual attachment validation.
References: 05, 21–22.

5. LEAVE REQUEST TRACKING — OBSERVED / GUIDE
Observed: total, pending, approved, rejected, cancelled counters; search;
status filters; type filters (Paid, Unpaid, Work From Home); sort by date/status;
result count and empty state. No requests available to inspect.
Guide: submission -> Pending -> one HR/Admin decision -> Approved or Rejected.
Rejection can include remarks. Approved leave may be cancelled before it ends:
cancellation request -> HR/Admin sign-off -> Cancelled; balance restored.
Guide: email/WhatsApp alerts to HR/Admin on submission; email/WhatsApp/in-app
alerts to employee on decision; balance and team calendar update immediately.
Unknown: request detail layout, pending-request withdrawal, cancellation denial,
intermediate cancellation states, attachment access, audit trail and actual alerts.
References: 06, 25, 16.

RESPONSIVE REQUIREMENT FOR THE NEW SYSTEM
Support mobile, tablet and desktop throughout all modules, dialogs and forms.
Use screenshots as references, not proof the current system is fully responsive.
Captured widths: 390px dashboard/apply-leave, 768px dashboard, 1440px
dashboard/apply-leave. Other captures use the default narrow browser viewport
(approximately 443px); original 01/02/03 filenames say desktop but are narrow.
Verify 320/390/768/1024/1440 widths, keyboard/focus, readable calendar/table
layouts, no clipped content, appropriate touch targets and validation states.
The 390px dashboard capture suggests right-edge crowding; check overflow in rebuild.
